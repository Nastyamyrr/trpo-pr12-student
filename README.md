# Практическая работа №12 — Vue 3. Options API

## Описание

Учебное приложение для управления задачами. Реализованы компоненты `App`, `FilterPanel`, `ItemList` и `ItemCard`, фильтрация по статусу, поиск по названию, добавление и удаление задач, изменение статуса, проверка формы и четыре интерфейсных состояния.

Исходные файлы `items.json`, `filters.json` и `ui_states.json` из dataset используются приложением как локальные JSON-модули.

## Технологии

- Vue 3
- Vite
- JavaScript
- HTML5 и CSS3
- JSON
- Options API

## Требования

- Node.js 20.19+ или 22.12+

## Запуск проекта

Откройте Terminal в папке проекта и выполните:

```bash
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://localhost:5173`. Откройте его в браузере.

## Production build

```bash
npm run build
npm run preview
```

Собранные файлы появятся в папке `dist`.

## Использование dataset

- `items.json` содержит 12 задач с полями `id`, `title`, `status`, `priority`. Данные отображаются карточками.
- `filters.json` задаёт четыре фильтра: «Все», «Новые», «В работе», «Готово».
- `ui_states.json` содержит сценарии `loading`, `error`, `empty`, `success`. В интерфейсе есть панель ручной проверки этих состояний.

JSON-файлы импортируются в `App.vue`. В `mounted()` вызывается `loadItems()`, который подготавливает список для отображения.

## Реализация Options API

- **data** — хранит задачи, фильтры, поисковую строку, значения формы, loading и error.
- **computed** — `visibleItems`, `totalCount`, `completedCount`, `activeCount` автоматически пересчитывают список и счётчики при изменении данных.
- **methods** — `loadItems`, `addItem`, `removeItem`, `selectItem`, `changeItemStatus`, `setDemoState`, `resetDemo` выполняют действия приложения.
- **props** — `FilterPanel` получает список фильтров и выбранные значения; `ItemList` получает массив задач; `ItemCard` получает одну задачу.
- **emits** — дочерние компоненты сообщают родителю об изменении фильтра, поиске, выборе, удалении и смене статуса.
- **mounted** — запускает загрузку локального dataset после создания и монтирования компонента.

Состояние массива принадлежит `App`. Дочерние компоненты не изменяют переданный объект напрямую, а отправляют события родителю.

## Проверка сценариев

1. Открыть главную страницу — отображаются 12 задач из `items.json`.
2. Нажать «Новые» — остаются задачи со статусом `new`.
3. Нажать «В работе» — остаются задачи со статусом `doing`.
4. Нажать «Готово» — остаются задачи со статусом `done`.
5. Ввести часть названия в поиск — список фильтруется.
6. Добавить задачу с названием — новая карточка появляется в списке.
7. Отправить пустую форму — рядом с полем появляется сообщение.
8. Нажать «Завершить» — статус задачи меняется на «Готово».
9. Удалить задачу — карточка исчезает, счётчик уменьшается.
10. Через «Проверить состояния» проверить Loading, Error, Empty и Success, затем нажать «Сбросить».

## Контрольные вопросы

1. **Какие входные данные получает приложение и где они находятся?** Приложение использует локальные JSON-файлы в `src/data`: список задач, фильтры и сценарии интерфейсных состояний.
2. **Какой участок кода отвечает за преобразование данных в интерфейс?** `App.vue` хранит и подготавливает состояние, а компоненты Vue отображают переданные через props данные.
3. **Какое ошибочное состояние проверялось вручную?** Состояние Error, в котором выводится сообщение об ошибке и кнопка повторного действия.
4. **Какие части решения можно изменить при увеличении проекта?** Можно добавить отдельный сервис работы с API, маршрутизацию, хранение данных и дополнительные компоненты.
5. **Как проверить работу после чистого клонирования репозитория?** Выполнить `npm install`, затем `npm run dev`; отдельно проверить `npm run build`.
6. **Чем Options API отличается от Composition API на уровне организации кода?** В Options API свойства компонента разделены на секции `data`, `computed`, `methods` и lifecycle hooks. В Composition API логика организуется внутри `setup()` с использованием функций Composition API.
7. **Как реактивное состояние влияет на повторный рендер компонента?** При изменении реактивных данных Vue автоматически обновляет те части интерфейса, которые зависят от этих данных.
